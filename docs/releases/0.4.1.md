# vsqlite++ 0.4.1

Patch release focused on hardening resource lifetimes, statement reuse, and the snapshot test/build
path after `v0.4.0`.

## Fixes

- Fixed `sqlite::result` lifetime so a result cursor keeps its prepared statement alive even when
  the creating `sqlite::query` object is destroyed first.
- Fixed `sqlite::connection_pool::lease::shared()` aliases so a shared connection can outlive the
  pool object without calling back into freed pool state.
- Fixed `sqlite::command::clear()` to clear retained SQLite parameter bindings before statement
  reuse. Use `reset_statement()` when intentionally preserving bindings.
- Fixed `sqlite::result::get_column_decltype()` for computed expressions and other columns where
  SQLite reports no declared type; it now returns an empty string instead of constructing from a
  null pointer.
- Hardened snapshot tests around `sqlite3_snapshot_open` preconditions and runtime SQLite feature
  availability.
- Fixed bundled SQLite build/export details, including deterministic test builds, amalgamation hash
  handling, and bundled include installation.

## Documentation

- Documented query-result lifetime, connection-pool alias behavior, command clearing semantics, and
  declared-type behavior for expression columns.
